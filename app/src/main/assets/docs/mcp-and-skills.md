# 工具服务与扩展能力设置

进入“设置” -> “工具服务”，管理 Model Context Protocol (MCP) 服务器配置，外挂本地或远程扩展能力（如查数据库、搜网页、浏览器控制等）。

## 1. 服务器列表页
*   列出所有已配置的 server 卡片，左侧图标区分 stdio（终端图标）/ HTTP（服务器图标），右下角状态圆点（已连接/连接中/连接失败/已禁用）。
*   每张卡片显示：名称、状态 Pill、类型 Pill（`内置` 或 `HTTP`）、信息 Pill（已连接时显示「工具: N」，否则显示启动命令或 URL）。
*   **左滑卡片**露出「删除」按钮可移除该 server；点击卡片进入编辑。
*   右上角「重新连接」按钮一键重连所有 server，「+」按钮添加新 server。

## 2. 编辑器：基础设置 Tab
顶部「是否启用」开关控制该 server 是否参与连接。其余字段按传输类型切换（`远程 HTTP` / `本地 stdio`）：

### 远程 HTTP 类型
*   **名称**：别名标识（如 `fetch`、`github`）。
*   **服务器地址**：远程服务端的 Streamable HTTP 链接（如 `https://api.example.com/sse`）。
*   **自定义请求头**：键值对列表，可添加多条，用于填入认证 Token 等静态头部。

### 本地 stdio 类型
*   **名称**：别名标识。
*   **启动命令**：执行引擎或命令，例如 `npx`、`node`、`python`。
*   **命令参数**：参数列表，每项一个卡片（如 `-y`、`@modelcontextprotocol/server-xxx`）。
*   **环境变量**：键值对列表，传递给该进程的环境变量（如 `API_KEY`）。

## 3. 编辑器：工具 Tab
连接成功后可查看该 server 暴露的工具列表，每个工具一张卡片：
*   **工具开关**：右上角 Switch 可禁用单个工具（写入 `disabledTools`），禁用后该工具不再注入模型。
*   **描述与参数**：显示工具描述及其入参键名 pill。
*   **需要审批**：底部 Switch 开启后，该工具每次调用前需用户确认（写入 `requireApprovalTools`）。
*   未连接或未检测到工具时，点击右上角「刷新」按钮重新拉取工具列表。

## 4. 其他入口
*   编辑器右上角日志按钮可跳转到「日志查看」并按该 server 名称过滤。
*   对于复杂的 MCP 配置，AI 也可在会话中通过 `manageMcp` 工具自动添加或管理。

## 5. 技能（Skills）
技能（Skill）是可复用的规则 / 脚本 / MCP 编排单元，供 AI 按需加载执行。技能管理位于「能力中心 -> 技能」Tab：
*   **执行形态**：PROMPT（注入指令，无执行）、SCRIPT（在容器内执行入口脚本，执行前需你确认）、MCP（已降级为别名：不再经技能系统执行，AI 直接调用其绑定的 MCP 工具）。
*   **作用域**：`全局`（所有 Agent、所有对话默认生效，可在设置中开关，也可在某个对话内临时禁用）／`Agent级`（仅对应 Agent 类型可用）／`对话级`（默认休眠，在对话页「技能」面板添加后仅在该对话生效）。
*   **列表管理**：技能按来源分组（内置 / 用户），支持关键词搜索、按执行形态筛选；每张卡片展示作用域、自动触发、类型与版本，可直接操作（查看 / 编辑 / 启用开关 / 卸载 / 导出）。
*   **查看技能**：点卡片「查看」进入技能详情页，页内「文件 / 详情」两个 Tab——「详情」展示元信息（名称/类型/来源/作用域/自动触发/版本/描述/标签）；「文件」默认显示 SKILL.md（无则优先 CLAUDE.md 或第一个文件，Markdown 可滚动阅读），顶部「目录」按钮或当前文件面包屑条可唤出半屏目录树（目录可折叠），浏览该技能的其它规则文档与脚本代码（代码带语法高亮、图片可预览）。
*   **导入技能**：顶部「导入」支持四种方式——ZIP 压缩包（含 SKILL.md 的技能目录打包）、单个 Markdown 文件、粘贴 Markdown 文本、从 URL 下载。导入前会做预校验，同名冲突时可选择覆盖或取消。
*   **编辑技能**：用户上传的技能（非内置）可在查看页或列表点「编辑」进入编辑器，以表单填写基本信息（名称/描述/版本/执行形态/作用域/自动触发/运行时依赖等）+ Markdown 编写指令正文，并支持新增/删除文件、另存为新技能。其中「运行时依赖」为布尔表达式（如 `cmd:node>=18 && (mod:numpy || cmd:python3)`），用于 SCRIPT 技能执行前的环境预检，缺失/版本不符会明确报错并给出安装建议。内置技能为只读，不可编辑或覆盖。
*   **内置只读**：随 App 预置的**内置技能**为只读，不可卸载或覆盖修改。
*   **内置技能「提交前规范体检」**：App 预置 `pre-commit-health`（提交前规范体检）。AI 在准备提交代码前可调用它，对工作区待提交改动做仓库纪律体检（模块文档同步、文本资源同步、版本号、敏感信息、依赖锁定、提交信息格式等），输出「阻断项 / 建议项」报告并据此修复，帮助您在正式提交前减少 CI 返工。该技能为 SCRIPT 型，执行前会弹出确认卡。
*   **内置技能「编程前准备」**：App 预置 `coding-preflight`（编程前准备）。AI 在开始编写/修改代码前（尤其新功能、重构、跨模块改动）可调用它，自动采集环境组件快照、Git 仓库状态（分支/游离/中间操作/未提交改动）、项目结构与模块清单，输出「就绪判定 + 计划建议」并引导任务理解、计划拆解与纪律自检，帮助您在动手前发现环境缺失、仓库状态脏等问题，减少中途返工。该技能为 SCRIPT 型，执行前会弹出确认卡。
*   **对话级技能**：对话输入框上方「技能」按钮可打开对话技能面板——查看本对话生效的技能、将「对话级」技能添加进当前对话（仅在当前对话生效）、或临时禁用某个全局/Agent 级技能（恢复后回到默认跟随声明）。
*   **自动触发（autoTrigger）**：部分技能可在 SKILL.md 中声明 `auto_trigger: true`、写明触发条件并给出高频触发信号词。此后新任务到来时，AI 会作为自动化流程的一环**由 AI 智能主导判断**任务意图是否应触发某技能（能理解口语化说法，如"帮我搞定一个 HTML 页面"也会识别为开发任务），命中即自动加载执行该技能并把结果注入本次任务参考，同一会话内不会重复触发。技能声明的信号词用于辅助 AI 判断；即使 AI 判断链路暂时不可用，也会回退用信号词兜底，保证"写代码/写页面/提交代码"这类明确任务不落空。**决策原则：AI（模型）判断优先于信号词，信号词不直接决定触发**。内置的「编程前准备」与「提交前规范体检」已开启自动触发：开始写/改代码前自动做编程前体检，准备 git 提交时自动做提交前体检。自动触发执行 SCRIPT 技能时仍会弹出确认卡（卡面带【自动触发】标记），由您确认后才执行，执行结果会以工具卡片展示在对话中。
