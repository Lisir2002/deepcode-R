# SOP-20 数据库迁移（Migration）

> 权威源：`AGENTS.md`「数据库与迁移」。新 5 库按域拆库 v1 起全新、无历史迁移链（agent 库已独立演进至 v4，其余仍 v1）；仅旧单库历史读取场景用文件驱动迁移。

## 1. 判断改动归属哪个库

- **操作**：按表归属定位库文件（agent / settings / credentials / workspace / t2i）。
- **判定**：目标表在哪个库 → 改动只落在该库；跨域表结构变更需先说明改动面。
- **产出**：确定目标库；出错（表归属不明）先查 `DataRegistry` 与库定义再继续。

## 2. 库内 schema 演进方式

- **操作**：新库 v1 起无历史迁移链，各库独立演进（agent 库已 v1→v4：v2 任务编排层表 / v3 运行轨迹表 / v4 剧本运行表）。若需在老库补迁移（仅历史读取场景），沿用 `MigrationLoader` 文件驱动迁移。
- **判定**：迁移 SQL 放 `app/src/main/assets/migrations/`，语句按 `;` 切分。
- **产出**：确定演进方式；误把新库当老库加迁移链则纠正方向。

## 3. 写迁移 SQL（防切分陷阱）

- **操作**：编写迁移 SQL 文件。
- **判定**：⚠️ SQL 字面量中不得出现 `;`（会被切分器误切），用 `char(59)` 代替字面量分号。
- **产出**：迁移 SQL 无 `;` 字面量；出错（启动即失败）检查是否含 `;`。

## 4. 联调 DataRegistry 与备份

- **操作**：新增/变更表后同步 `core/data/DataRegistry` 登记。
- **判定**：备份/恢复/自动迁移统一经 DataRegistry 全量导出/导入，新表在登记列表中。
- **产出**：备份覆盖新表；漏登记则补登。

## 5. 验证迁移

- **操作**：编译 + 冒烟测试迁移路径。
- **判定**：`./gradlew :app:assembleDebug` 通过；启动不报迁移失败。
- **产出**：迁移验证通过；失败按常见坑表排查（含 `;` 误切）。
