# 编程前准备（coding-preflight）

## 何时使用（激活触发词）
在用户给出一个新任务、你**准备动手写代码之前**，主动调用本技能做一次「开工前体检」。尤其适合：
- 新功能 / 重构 / 跨模块改动 / 涉新文件较多；
- 你对当前项目结构、构建环境、仓库状态不熟悉（新会话/新仓库/长时间未操作）；
- 任务涉及安装依赖、构建、运行，需先确认环境是否就绪。

它与 pre-commit-health（提交前体检）互补：本技能在**动手前**把关「能不能开始、从哪开始」，前者在**提交前**把关「改得对不对」。

触发场景：用户说"开始写/开始做/帮我实现/开发一个/重构/新功能"，或你判断这是一个需要多步完成的编程任务时。

## 调用方式
- 请求执行本技能，传入参数：
  - `task`（可选）：用户任务的一句话描述，脚本会原样输出在 `[任务]` 行，供计划引导参考。缺省为空。
  - `project_path`（可选）：项目目录。缺省时工具自动以容器内 `/root/workspace` 作为项目路径。
- 执行后得到一份 UTF-8 报告，包含：`[项目]/[类型]/[任务]/[环境]/[仓库]/[结构]` 现状快照，
  **就绪判定（❌ 阻断项 / ⚠️ 建议项）**，以及末尾的 `[计划] 建议步骤`。

## 输出解读与修复口径

### 现状快照（供理解，非判定）
- `[项目]` 仓库根路径；`[类型]` **按通用栈识别**（Android/Web前端/Node后端/PHP/Python/Go/Rust/Java/C/C++/空工作区/脚本工程/通用工程，可多标签并存），不再用「非 Android 项目」这种先入为主的表述。
- `[类型说明]` 类型的补充说明：多栈并存的提示交集原则、空工作区提示先明确技术栈等。
- `[环境]` 按类型精确探测的组件快照：`组件=installed(版本)/missing`（Git 始终探测；PHP/Node/Go/Cargo/Java/Android 按类型）。
- `[仓库]` 当前分支、是否游离、是否有未提交改动及数量、是否处于 merge/rebase 等中间操作、最近提交；**未初始化为 git 时额外打 W-1 建议 git init**。
- `[结构]` Android 下 feature 模块 + docs 目录存在性；其它类型下「根目录顶层 DIR/FILE 清单」。
- `[文件]` **4 份基础资产（AGENTS.md/README.md/.gitignore/.gitattributes）** 存在性；缺失时脚本报告末尾会附带【文档模板】段，内含通用最小可用版本。

### 阻断项（❌，存在则先处理再动手）
- `R-1 环境缺关键组件`：按识别类型精确匹配的构建组件为 missing（如 PHP 工程缺 php / Go 工程缺 go / Java 工程缺 java 等）。→ 先安装或说明降级，否则写完构建失败再返工。
- `R-2 仓库中间操作`：仓库正处于 merge/rebase/cherry-pick/revert 进行中。→ 先完成或中止再开始新任务。
- `R-3 游离 HEAD`：当前为 detached HEAD。→ 先 checkout 分支再开工。
- `R-4 有未提交改动`：工作区有未提交改动且用户任务主题不同。→ 先 stash/提交再开工。
- `R-5 错误分支`：功能/重构类大改动在 main/master。→ 建议先 feat/xxx 分支再开工。

### 建议项（⚠️，**软阻断：写业务代码前必须全部处理**）
- `W-1 仓库未初始化`：工作区不是 git 仓库。→ 先执行 `git init`，便于回溯与回滚。
- `W-2 模块文档未读`：涉及 feature 模块时先读 docs/modules/<模块>.md 了解约束。
- `W-3 资产同步面预判`：改动若涉 AI 工作流/UI 文案/新增模块，提前规划 strings.xml / assets/prompts / assets/docs / docs/modules 同步。
- `W-4 危险/敏感操作前置询问`：任务含删除/重构/改 schema/发版等 Ask First 项，先与用户确认再动手。
- `W-5 无任务描述`：未传 task 时先用询问工具澄清。
- **`W-6 纪律文档缺失（AGENTS.md）→ 必须先创建`**：脚本报告末尾【文档模板】段已附带通用最小可用版本（含边界规则 Always/Ask First/Never、提交规范、资产同步纪律），直接 writeFile 写入即可，不需编造内容。
- **`W-7 说明文档缺失（README.md）→ 必须先补`**：报告末尾【文档模板】段已附带按识别类型生成的最小 README（技术栈/运行方式/接口约定/目录结构/环境要求/开发规范），直接 writeFile 再按需补内容。
- **`W-8 忽略配置缺失（.gitignore）→ 必须先创建`**：报告末尾【文档模板】段已附带按识别类型生成的最小忽略规则（语言/构建产物/IDE/临时文件），直接 writeFile。
- **`W-9 属性配置缺失（.gitattributes）→ 必须先创建`**：报告末尾【文档模板】段已附带通用最小规则（文本 LF 规范化 + 源码 diff 语言识别 + 二进制声明），直接 writeFile。

### 就绪判定（强语义）
- `❌ 阻断项 > 0`：先处理阻断项，否则写码必返工。
- `🛑 建议项 > 0（软阻断）`：W-6~W-9 + W-1 属于「基础资产/纪律」，必须在业务代码前 writeFile 补全；脚本退出码会以非 0 表示软阻断，调用方据此强制先补资产。
- 仅当两项均为 0 时，才视为真正「就绪」。

### 计划引导（必须按序执行）
1. **任务理解**：复述需求；识别目标文件/模块；不确定信息用只读工具核实，不凭记忆。
2. **补齐基础资产**：按 W-* 条目 + 报告末尾【文档模板】段，先 writeFile 补全缺失的 AGENTS.md/README.md/.gitignore/.gitattributes；W-1 未初始化仓库先 git init。**这一步在写任何业务代码前完成。**
3. **记忆加载**：用 memory 工具查看项目记忆，加载「坑」类经验。
4. **模块文档**：涉及 feature/模块/子系统时先读 docs/modules/。
5. **计划拆解**：输出可执行步骤，每步含「做什么/涉及文件/如何验证」，步骤多时用待办清单登记。
6. **验收标准**：明确「完成 = 什么可观测结果」（构建通过/测试全绿/接口返回/页面渲染/文档同步）。
7. **纪律自检**：对照 AGENTS.md 边界规则，列出本次改动的资产同步项与需先询问项。

## 纪律
- 本技能**只读**：只采集现状并输出报告，不修改、不提交任何文件；安装环境/清仓库/建分支等动作由你依据报告执行。
- 有阻断项（R-*）时，先处理再动手写代码；处理完可重跑本技能确认绿灯。
- 与 pre-commit-health 配合：开工前跑本技能，提交前跑 pre-commit-health。

## 故障口径（脚本报错时）
1. **只读不修**：报告或脚本发现问题时，不要在调用侧修改技能资产（`entry/run.sh`、`SKILL.md`），技能资产为内置只读资产，由维护者修完重新发版。
2. **先复核再报错**：先确认是「脚本 bug」（本机 `sh -n` 验证）还是「环境缺依赖」（git/grep/sed/awk 缺失）。
3. **降级不硬崩**：个别采集/判定因缺工具无法执行时，跳过该项并提示「部分降级」，不整体失败。
4. **如实报告**：无法完成时如实向用户说明原因，不编造现状结论。
