# 编程前准备（coding-preflight）

## 何时使用（激活触发词）
在用户给出一个新任务、你**准备动手写代码之前**，主动调用本技能做一次「开工前体检」。尤其适合：
- 新功能 / 重构 / 跨模块改动 / 涉新文件较多；
- 你对当前项目结构、构建环境、仓库状态不熟悉（新会话/新仓库/长时间未操作）；
- 任务涉及安装依赖、构建、运行，需先确认环境是否就绪。

它与 pre-commit-health（提交前体检）互补：本技能在**动手前**把关「能不能开始、从哪开始」，前者在**提交前**把关「改得对不对」。

触发场景：用户说"开始写/开始做/帮我实现/开发一个/重构/新功能"，或你判断这是一个需要多步完成的编程任务时。

## 调用方式
- 请求执行本技能，传入参数：
  - `task`（可选）：用户任务的一句话描述，脚本会原样输出在 `[任务]` 行，供计划引导参考。缺省为空。
  - `project_path`（可选）：项目目录。缺省时工具自动以容器内 `/root/workspace` 作为项目路径。
- 执行后得到一份 UTF-8 报告，包含：`[项目]/[类型]/[任务]/[环境]/[仓库]/[结构]` 现状快照，
  **就绪判定（❌ 阻断项 / ⚠️ 建议项）**，以及末尾的 `[计划] 建议步骤`。

## 输出解读与修复口径

### 现状快照（供理解，非判定）
- `[项目]` 仓库根路径；`[类型]` Android 项目 / 非 Android 项目（脚本据此决定是否提示 Android 专属资产同步）。
- `[环境]` 按项目栈推断的组件快照：`组件=installed(版本)/missing`（如 Java、Gradle、Android SDK、Node、Go、Cargo 等，Git 始终探测）。
- `[仓库]` 当前分支、是否游离、是否有未提交改动及数量、是否处于 merge/rebase 等中间操作、最近提交。
- `[结构]` feature 模块清单、`docs/modules/` 已有文档、`docs/plan-docs/`/`assets/prompts/`/`assets/docs/` 存在性。

### 阻断项（❌，存在则先处理再动手）
- `R-1 环境缺关键组件`：项目栈推断的构建组件探测为 missing。→ 先安装（如 `apk add` 或按项目文档安装 JDK/Android SDK/Node 等），否则写完构建失败再返工；确需降级（如纯文档任务）可说明后继续。
- `R-2 仓库中间操作`：仓库正处于 merge/rebase/cherry-pick/revert 进行中。→ 先完成（`git merge --continue`/`rebase --continue`）或中止（`--abort`）再开始新任务。
- `R-3 游离 HEAD`：当前为 detached HEAD。→ 先 `git checkout <branch>` 再开工，防新提交丢失。
- `R-4 有未提交改动`：工作区有未提交改动（尤其跨多模块/含未跟踪新文件）。→ 与用户确认：属同一主题可继续，否则先 `git stash` 或提交当前改动，避免新旧混杂。
- `R-5 错误分支`：新任务为功能/重构但当前在 `main`/`master` 且改动面较大。→ 建议先 `git checkout -b feat/xxx` 再开工（遵循分支纪律）。

### 建议项（⚠️，提醒，不强阻断）
- `W-1 记忆未加载`：用 `memory` 工具查看项目记忆，加载相关条目（尤其「坑」类历史踩坑经验）。
- `W-2 模块文档未读`：涉及 feature 模块时，先读 `docs/modules/<模块>.md` 了解架构约束与对外接口。
- `W-3 资产同步面预判`：改动若涉 AI 工作流/UI 文案/新增模块，预先规划 `strings.xml`（中/英）、`assets/prompts/`、`assets/docs/`、`docs/modules/` 的同步（对应 AGENTS.md 资产同步纪律）。
- `W-4 危险/敏感操作前置询问`：任务含删除/重构/改 schema/发版等 Ask First 项，先与用户确认再动手。
- `W-5 无任务描述`：未传入 `task` 时，先向用户澄清需求（用询问工具）再拆解，避免做错方向。

### 计划引导（依据报告完成）
1. **任务理解**：复述用户需求；识别目标文件/模块；对不确定的信息用只读工具（list/readFile/search）核实，**不凭记忆**。
2. **计划拆解**：输出可执行步骤（1..N），每步含「做什么 / 涉及哪些文件 / 如何验证」；步骤多时用待办清单工具登记。
3. **验收标准**：明确「完成 = 什么可观测结果」（如构建通过、测试全绿、文档同步）。
4. **纪律自检**：对照 AGENTS.md 边界规则（Always / Ask First / Never），列出本次改动的资产同步项与需先询问项。

## 纪律
- 本技能**只读**：只采集现状并输出报告，不修改、不提交任何文件；安装环境/清仓库/建分支等动作由你依据报告执行。
- 有阻断项（R-*）时，先处理再动手写代码；处理完可重跑本技能确认绿灯。
- 与 pre-commit-health 配合：开工前跑本技能，提交前跑 pre-commit-health。

## 故障口径（脚本报错时）
1. **只读不修**：报告或脚本发现问题时，不要在调用侧修改技能资产（`entry/run.sh`、`SKILL.md`），技能资产为内置只读资产，由维护者修完重新发版。
2. **先复核再报错**：先确认是「脚本 bug」（本机 `sh -n` 验证）还是「环境缺依赖」（git/grep/sed/awk 缺失）。
3. **降级不硬崩**：个别采集/判定因缺工具无法执行时，跳过该项并提示「部分降级」，不整体失败。
4. **如实报告**：无法完成时如实向用户说明原因，不编造现状结论。
